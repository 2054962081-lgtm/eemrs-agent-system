# 报告纵向分析上下文融合与前端展示说明

## 一、功能目标

第二阶段在报告纵向分析基础上增加脱敏预问诊上下文、长期健康档案和分诊上下文，让医生端摘要和患者端解释能同时参考报告趋势、当前症状、历史疾病和推荐科室。

本阶段只做旁路增强，不改变预问诊问答、科室推荐、报告解密、指标标准化、异常检测、趋势计算、挂号、医生列表、登录权限和既有评测逻辑。

## 二、为什么要接入预问诊上下文

单独的检验趋势只能说明指标变化，不能说明患者当前症状背景。接入脱敏后的症状标签、危险信号标签、推荐科室和慢病标签后，云端模型可以生成更贴近就医沟通的摘要，例如提示医生结合体温、病程和体格检查继续判断，而不是只复述指标升高。

## 三、端云架构变化

本地侧新增 `ReportTrendContextService`，在报告趋势分析流程中按请求开关读取上下文。旧调用方不传 `includePreconsultationContext` 或 `includeLongTermHealthContext` 时，默认不使用上下文。

云端 payload 仍由本地 allowlist 构造并经过 `CloudPayloadPrivacyGuard` 检查。云端只接收脱敏结构化摘要，不接收完整问诊原文、完整病历原文、完整报告原文、密文、密钥或患者身份信息。

## 四、上下文来源

当前实现按可用性读取：

1. 当前 `sessionId` 对应的预问诊病历草稿。
2. 患者最近的深度预问诊病历草稿。
3. `user_long_term_memory` 中的长期健康记忆。
4. 草稿中的推荐科室作为分诊上下文。

如果某一类上下文不存在，服务返回 `available=false` 并继续报告趋势分析。

## 五、上下文字段脱敏策略

本地只抽取标签和桶化信息：

- 症状标签，例如发热、咳嗽、咽痛。
- 症状持续时间桶，例如 1-3 天。
- 危险信号标签。
- 慢病标签，例如糖尿病、高血压。
- 是否已知过敏。
- 推荐科室和是否建议挂号。

不会把完整主诉、完整问诊对话、完整病历、姓名、身份证号、手机号、patientId、doctorId 或 visitId 放入云端 payload。

## 六、云端 payload 白名单

允许的顶层字段为：

- `analysis_task`
- `report_type`
- `date_range`
- `coarse_patient_context`
- `normalized_items`
- `trend_results`
- `abnormal_summary`
- `symptom_context_summary`
- `health_context_summary`
- `triage_context_summary`
- `output_requirements`

如果出现未在白名单内的顶层字段，或出现患者身份字段、密文字段、密钥字段、鉴权字段、身份证号或手机号模式，云端调用会被阻断。

## 七、云端提示词输出结构

云端提示词要求返回 JSON，并包含：

- 医生端摘要。
- 患者端解释。
- 结合上下文解释。
- 关键异常指标。
- 报告和症状关联提示。
- 风险提示。
- 建议进一步询问的问题。
- 建议科室。
- 建议行动。

提示词明确禁止确诊、开药、推荐具体药物、替代医生判断、夸大风险和生成治疗方案。

## 八、医生端展示内容

医生端在接诊页面增加“报告纵向分析”卡片，展示：

- 分析编号和反馈编号。
- 报告趋势指标。
- 异常指标。
- 医生端摘要。
- 患者端解释。
- 结合症状提示。
- 报告和症状关联提示。
- 建议进一步询问的问题。
- 建议科室和建议行动。

医生端不展示云端 payload、模型原始提示词、密文、密钥或完整 Trace 详情。

## 九、患者端展示内容

患者端在报告查询页面增加“报告纵向分析”卡片，展示：

- 分析状态。
- 异常指标。
- 趋势变化。
- 患者端解释。
- 结合症状提示。
- 建议进一步补充的问题。
- 建议科室。
- 建议行动。
- 反馈编号。

患者端不展示医生端专业摘要、内部 Trace 详情、云端 payload、模型原始输出和敏感身份信息。

## 十、Trace 记录步骤

新增或接入的步骤包括：

- `CONTEXT_QUERY`
- `PRECONSULTATION_CONTEXT_LOAD`
- `LONG_TERM_HEALTH_CONTEXT_LOAD`
- `TRIAGE_CONTEXT_LOAD`
- `CONTEXT_REDACT`
- `CONTEXT_FUSION`
- `CLOUD_PAYLOAD_BUILD`
- `CLOUD_MODEL_REQUEST`
- `CLOUD_MODEL_RESPONSE`
- `FINAL_REPORT_SUMMARY`

Trace 只记录上下文是否可用、标签数量、推荐科室、上下文摘要哈希、状态和错误码，不保存完整问诊原文。

## 十一、隐私边界

本地负责读取密文报告、解密、脱敏、结构化、趋势计算、上下文聚合和隐私检查。云端只负责基于脱敏结构化数据生成摘要。

分析结果继续加密存储，数据库不保存完整明文报告、不保存完整云端 payload、不保存完整云端回复、不保存密钥。

## 十二、权限边界

本阶段不新增公开绕行接口，不放宽现有登录和角色路由约束。患者端使用当前登录患者标识发起分析；医生端在接诊页面内对当前接诊患者发起分析。

后端接口保持原报告纵向分析入口，新增参数都是可选项。严格接诊范围校验仍应由现有业务权限体系继续承载。

## 十三、错误处理

患者端展示友好提示：

- 报告数据不足，暂无法生成趋势分析。
- 报告解析失败，请联系医生查看原始报告。
- 系统暂时无法生成分析，请稍后重试。

医生端可附带内部错误码，但仍不展示敏感内容。

## 十四、测试方法

后端：

```bash
cd agent-server
mvn -q test
```

前端：

```bash
cd frontend-vue
npm.cmd run build
```

RAG 回归：

```bash
python -m unittest rag.test_rag_trace_meta
```

自动化测试不得调用真实云端接口，不得提交真实密钥或真实患者数据。

## 十五、当前不做的内容

本阶段不做报告纵向分析接入 Harness V2 评测、不做评测结果文件生成、不做大模型裁判、不做语义相似度评测、不做 OCR、不做影像报告、不做自动诊断、不做自动开药、不做自动检查申请、不做复杂图表大屏、不做管理员 Dashboard、不做 CI 自动评测。

## 十六、后续计划

后续可以把上下文抽取从关键词升级为更稳定的结构化字段读取；在权限体系具备接诊范围判断后，进一步收紧医生端分析权限；再根据需要单独实现 Report Trend 到 Harness V2 的评测适配。
